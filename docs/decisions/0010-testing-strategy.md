# ADR-0010: Testing strategy and the honest coverage gate

## Status

Accepted

## Date

2026-09-13

## Context

The project standard is 100% coverage. Flutter projects contain code that genuinely cannot execute
under the VM test host (platform-conditional imports, generated files), so a literal 100% target
is either a lie or an invitation to write tests that assert nothing.

## Decision

Follow the `dart-add-unit-test`, `flutter-add-widget-test`, and `flutter-add-integration-test`
skills: the test tree mirrors `lib/` file for file, `group()` per class, `setUp()` for fakes,
mocks generated by `mockito`'s `@GenerateMocks`. Widget tests pump inside
`MaterialApp` + `ProviderScope(overrides:)` and assert loading, data, empty, and error states.
Integration tests live in `integration_test/` with the host driver at
`test_driver/integration_test.dart`, and every interactive widget carries a `ValueKey`.

The coverage gate requires 100% of measured lines, where generated output (`*.g.dart`,
`*.freezed.dart`, generated l10n) and platform-conditional files are excluded by
`tool/coverage.sh`. Exclusions are listed explicitly in that script, not globbed loosely.

## Alternatives Considered

### `mocktail` instead of `mockito`

- Pros: no codegen, no `@GenerateMocks` annotations.
- Cons: the skill names `mockito`, and generated mocks match this project's codegen-first stance.
- Rejected.

### Claim 100% with no exclusions

- Pros: a clean number on the badge.
- Cons: requires either untestable-code gymnastics or assertion-free tests.
- Rejected: an explicit exclusion list is more honest than a padded number.

## Consequences

- The web drift connection is excluded from unit coverage and is instead exercised by the Chrome
  integration job. If that job is skipped, that code is unverified — stated here so it is not
  discovered later.
- Two deliberate deviations from the integration skill: `enableFlutterDriverExtension()` is not
  called, because it belongs to legacy `flutter_driver` and would put test-only code in the
  production entry point; and the skill's MCP exploration step (`launch_app`, `get_widget_tree`)
  is skipped because the Dart MCP server was unavailable, so tests were authored from widget code.
